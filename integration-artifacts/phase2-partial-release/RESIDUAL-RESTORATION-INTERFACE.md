# Residual restoration integration artifact

Review-only incremental patch, based on local `a5ca0e9119bf1cce1e0a6b794a88e5dc95ebfeba` (the prior release and increase artifacts). It requires the existing payment-attempt guard and shared active-line tombstone migration. Reconcile the `CREATE OR REPLACE` tombstone guard with the current #1377 pack work; do not overwrite newer safety checks. Do not enable editing, void or removal until the reader owner integrates this with current active-allocation, pack-binding and clinical readers and runs their full race suite.

`pharmacy_allocation_residual_restorations` is append-only, tenant-scoped and unique by `(organizationId, allocationId)`, `(organizationId, stockMovementId)` and `(organizationId, idempotencyKey)`. Its fields are `id`, `organizationId`, `branchId`, `allocationId`, `stockMovementId`, `idempotencyKey`, `actorId`, `reason`, `canonicalUnits`, `grossMinor`, `createdAt`. A row links one separately posted ADJUSTMENT to the remaining portion of an original SALE; `reversesMovementId` remains null, preserving the existing exact full-reversal invariant. The database locks the scoped sale, applies the unresolved-attempt guard and separate unpaid checks, requires the same-transaction adjustment with matching actor/reason/lot/location/disposition/arrangement, and enforces exactly `original - SUM(partial releases)` units and original gross less released gross. A deferred check requires that the same transaction ends with the line tombstoned or sale VOID; if a residual record finalizes a void, every active line must have complete allocation restoration. The existing full-reversal barrier remains in place.

`restoreAllocationResidual(db, scope, { saleId, saleLineId, allocationId, idempotencyKey, reason })` is internal: the caller must authorize actor and branch, own the transaction and complete its void or removal before commit. Its results are `FULL_REVERSAL_REQUIRED` when no partial release exists (use the existing exact full reversal), `ALREADY_RELEASED` when partial releases restored the whole allocation (do not create a movement), or `RESTORED` with `stockMovementId` and `replayed`. Reusing the same request key, actor and trimmed reason after a committed restoration returns the existing movement; changing those inputs conflicts. For `ALREADY_RELEASED`, operation-level void/removal retries still need their existing sale-level idempotency. Missing/inconsistent price or stock evidence fails closed.

`pharmacy_allocation_restoration_complete(org, branch, allocation)` is available to the reader's void/removal implementation. A never-partially-released allocation requires its exact original reversal; a partly released allocation requires either releases covering the whole original or a matching residual record, and must not have a full reversal. Explicitly check every active allocation, even when a void involves only fully released allocations and therefore inserts no residual record. For removal, migration `20261106160000_pharmacy_residual_restoration` replaces the existing tombstone guard to use this helper while retaining the original unpaid, actor and controlled-register checks. Mixed untouched and partially released allocations must be restored in the same transaction.

Partially released Rx, restricted, controlled, high-alert, reviewed, substituted or prescription-linked lines fail closed. Existing untouched controlled allocations still require the existing dispensing authority, independent witness and correction register workflow. Pack binding and scan mismatch checks are not integrated. Do not expose this helper directly or treat this artifact as a complete void implementation.

Fresh migrations were applied to a disposable PostgreSQL clone with the active-line and payment foundations; runtime role was NOSUPERUSER/NOBYPASSRLS and test grants on new tables were supplied. Typecheck, changed-file lint, Prisma validation and 74 focused tests passed. Tests exercised partial release then synthetic void or tombstone, mixed full and residual restoration, rollback if finalization or other allocation restoration is missing, duplicate/concurrent retry, tenant/branch refusal, controlled-change refusal, residual-versus-reduction in both orders and residual-versus-payment preparation in both orders. These tests do not replace integration tests of the real router, actual void workflow, pack worker or controlled partial restoration.
