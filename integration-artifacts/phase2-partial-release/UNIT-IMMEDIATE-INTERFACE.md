# Unit change and immediate-add integration artifact

Review-only incremental patch based on local residual head `50b3a48c4ad781ebc75e5d032be0c8e4299b61aa`. Apply after the earlier partial-release, increase/reversal and residual artifacts and reconcile current #1377 pack/safety and the reader owner's void/removal integration. The migrations are ordered 1100, 1200, 1300, 1400, 1500, 1600, 1700; preserve deferred constraints. No router, UI wiring, authorization or deployment is enabled by this patch.

`counter-line-command.ts` exports strict Zod command schemas `immediateAddLineSchema`, `changeLineQuantitySchema` and `changeLineUnitSchema`. These validate shape, not permissions. The future authenticated router must check the actor's real counter capability and branch assignment, own each transaction through commit, handle failures in `counter-messages.ts`, and not expose these commands before active-allocation, pack and clinical integration. Commands use expected prior quantity/unit and a stable user-action idempotency key. A retry can report its historical result; refresh the authoritative cart afterwards.

`immediateAddSaleLine(db, scope, input)` adds one selected unit to an unpaid open sale under the existing scoped sale/payment lock. An exact matching active medicine/unit/presentation/pack line is increased through the existing FEFO increase transaction; no matching line is created through the existing stock writer and each selected lot's pack hierarchy is checked. Ambiguous duplicate or mismatched lines, unsupported units, unknown stock and non-OTC/Rx/restricted/controlled/high-alert medicines fail closed. The latter must continue through the existing clinical workflow, not be treated as authorized. `pharmacy_immediate_add_requests` records scoped request/replay evidence. Concurrent duplicate request keys replay once; distinct requests serialize on the sale. Pack scan binding and confirmed mismatch checks remain unintegrated.

`changeSaleLineUnit(db, scope, input)` changes pack/strip/unit only when the existing canonical units divide exactly into the selected unit, every retained lot supports the same target hierarchy, and the retained gross does not exceed a conservative cap derived from immutable captured prices. It preserves stock movements, canonical units, lot evidence and gross, recalculates display unit price and retained cost, and clears discount/approval. A conversion can intentionally refuse: for example a 201-minor pack of two cannot become two units at a captured 100-minor per-unit ceiling while preserving its 201 gross. This needs clear product copy, not a fabricated lower price. `pharmacy_sale_line_unit_changes` provides append-only request and audit evidence; guards require same-transaction matching state, actor, tenant/branch, valid retained lot hierarchy, price cap, unpaid status and clinical restrictions. The actor and branch still require application-level authorization.

Quantity increase now validates that all newly allocated lots support the line's sale unit and accepts older snapshots with a different denominator after unit conversion. Reduction recomputes retained unit cost using the current remaining lot costs. Discount reapplication still needs the separate supervised approval implementation and must recompute/enforce below-cost and regulated restrictions under the authoritative lock; these commands only clear an existing discount.

Tests include synthetic database operations, not the actual UI, real void/removal routes or #1377 pack integration.
