Branch `fix/qa-129-sindh-regulatory-profile` at `ee28700c`. Fresh database `devfathom_162c`. Tenant `http://qa-sindh162c.localhost:3000`.

### Deploy still stops before Sindh is published

`prisma migrate deploy` as `devfathom_migrator` failed on `20261021110500_pharmacy_sindh_published_rules`:

> new row violates row-level security policy for table "pharmacy_jurisdiction_rule_sets"

The file sets `app.is_platform_admin` with `set_config(..., true)` and then inserts. The same file succeeds inside an explicit `BEGIN` / `COMMIT`, and that insert already carries `pendingLegalReview: true` on `PK-SD`. `PK-PB` stays provisional.

After that insert was committed by hand and the migration row marked finished, `prisma migrate deploy` continued and failed on `20261021111000_pharmacy_sindh_pending_review_and_province_checks`:

> pharmacy_jurisdiction_rule_sets is append-only; create a new effective-dated version

The same `UPDATE` fails inside an explicit transaction with the platform flag set. The immutability trigger rejects stamping `pendingLegalReview` onto the existing `pk_sd_published_v1` row. A database that already has the row cannot take this follow-up, and a fresh deploy never gets past the insert.

The app checks below ran only after the insert had been applied in a transaction, the follow-up’s province checks were applied without the rejected update, and that migration row was marked finished so the later migrations could run.
