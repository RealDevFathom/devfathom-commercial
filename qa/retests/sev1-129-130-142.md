### Migrate deploy does not publish Sindh

`prisma migrate deploy` as `devfathom_migrator` stopped on `20261021110000_pharmacy_sindh_published_rules`:

> new row violates row-level security policy for table "pharmacy_jurisdiction_rule_sets"

### 1. Sindh jurisdiction migration does not apply under `prisma migrate deploy`

**Title:** `prisma migrate deploy` fails the Sindh rule insert on a NOSUPERUSER migrator (`d4c2c45b`)

**What happened:** On a new database, `prisma migrate deploy` as `devfathom_migrator` (`NOSUPERUSER`, `NOBYPASSRLS`) failed in `20261021110000_pharmacy_sindh_published_rules` with `new row violates row-level security policy for table "pharmacy_jurisdiction_rule_sets"`. The migration is recorded as failed. Only provisional `PK-PB` is present, so a Sindh branch still has no published rules. The same SQL succeeds when it is run inside an explicit `BEGIN` / `COMMIT`. The file sets `app.is_platform_admin` with `set_config(..., true)`, which is local to the current transaction and is not visible to the INSERT the way `prisma migrate deploy` executes the file.

**Where:** `prisma/migrations/20261021110000_pharmacy_sindh_published_rules/migration.sql` at `d4c2c45b`.

That row was stored and `PREMISES_AND_LICENCES` became `DONE`.

**Where:** `pharmacyOnboarding.saveRegulatoryProfile` in `src/server/routers/pharmacy-onboarding.ts` at `d4c2c45b`. Tenant `qa-sindh129b`, branch Clifton Chemist (`PK-SD`).
