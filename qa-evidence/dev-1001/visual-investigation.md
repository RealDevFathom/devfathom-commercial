# Visual QA investigation history

The final matrix is summarized separately in `visual-report.md`. The harness was developed against isolated real components; intermediate failures below are not silently counted as passes.

- Initial registration screenshots showed an undersized visible trigger and mobile overflow after migration. The product fix extended the existing auth/platform field selectors to the shared trigger and clamped hidden form-control geometry. All three registration variants were recaptured at 375/768/1024/1440, light/dark, normal/reduced motion.
- The Notes toolbar initially squeezed the selected “Private” value. A shrink-resistant wrapper restored the value. The final mobile capture shows it. The adjacent Share button already clips in the baseline and was not changed by this migration.
- The clients, HR, restaurant money and hotel function-space fixtures overflow at 375px. Immutable baseline captures reproduce widths 581, 389, 391 and 462px respectively. The first three use unwrapped tab lists; the hotel booking form sits inside an already wide table layout. These layouts predate the selector migration. These remain reported failures of the document-overflow check.
- Initial catalog/email keyboard probes sent Escape before the opened popup had completed focus transfer. The harness now waits for a visible listbox and waits for focus restoration; the original strict focus and Tab assertions remain. Both families were rerun through all 16 combinations.
- Initial staff keyboard probes directly focused background filters while its modal was open. The harness now scopes interactions to the active dialog. A second mismatch pressed Escape after ArrowDown on the retained native branch picker: ArrowDown changes native selection without opening a DOM popup, and Escape dismisses the parent dialog. Native controls now check ArrowDown and Tab; shared controls still require an opened listbox, Escape focus restoration, and Tab departure. Final staff results are separately recaptured. Native controls are documented exceptions, not migrated popup controls.
- Early fixture probes exposed incomplete synthetic query response shapes and a malformed sample PNG. Those local fixture inputs were corrected before the final matrix. No backend/service behavior was changed, no live requests were made, and no existing test assertions were weakened.

`*-keyboard-failure.png` artifacts preserve intermediate keyboard failures; they are investigation evidence, not final passing captures. Filenames ending `-open.png` describe the keyboard capture point: retained native pickers may show only focus, and one-option menus may visually coincide with their trigger. DOM listbox visibility is asserted for shared controls. Screenshots alone must not be treated as proof that a native operating-system popup was visible.

Expanded restaurant server-page fixtures initially converted static JSX children to dynamic arrays, emitting React missing-key warnings. The local resolver now preserves the static sibling call shape. Final purchasing/report matrix runs use that corrected resolver. Baseline bundling also uses the existing generated Prisma browser/enumeration files from the unchanged schema, since generated files are not tracked in the baseline commit.

After the resumed no-hosting instruction, no QA HTTP listener remained. The runner now pre-reads its static bundle/assets and supplies them only through Playwright `route.fulfill` at the reserved `https://dev1001.invalid` origin; all unmatched requests are aborted. This preserves ordinary query/storage semantics without a local/LAN server or outbound connection. Chromium refused `file://` navigation under administrator policy; no browser policy was changed. Earlier saved captures used isolated cloud loopback before the instruction and are retained as historical evidence, not relabeled as new runs.

A second investigation reproduced apparent Escape failures only when an open-menu screenshot forced full-page/animation changes. That capture can dismiss a popup before Escape, allowing Escape to reach the surrounding editor. The final open-menu capture uses the actual viewport without forced animation completion and asserts that keyboard focus remains inside the popup after the capture. The affected hotel desktop probe then passed with unchanged product code. Eight related families are recaptured with strict popup focus, visible focus, Escape and Tab checks; final results are reported from saved metrics.

The visual matrix uses actual browser ArrowDown/Escape/Tab. It does not claim Enter selection coverage. Actual browser End/Enter selection and form submission are separate browser-form evidence. The per-control jsdom suite sends End/Enter and then an explicit zero-detail click to emulate keyboard activation's default action; that fallback is disclosed as such.
