# Private Restaurant initializer source contract

This is source preparation, not an approved execution packet. No target was connected during development. The canonical `production-bootstrap.ts` is byte-unchanged. There is one writer, one private pool (max 1), one owning serializable transaction, and no automatic retry.

## Private commands

Use the existing locked Node/tsx tooling from the composed source root:

```
TSX_DISABLE_CACHE=1 TSX_TSCONFIG_PATH=prisma/tsconfig.fresh-database.json node --import tsx prisma/fresh-database-runner.ts validate /private/config.json /private/approval.json APPROVAL_SHA256_FROM_COORDINATOR
TSX_DISABLE_CACHE=1 TSX_TSCONFIG_PATH=prisma/tsconfig.fresh-database.json node --import tsx prisma/fresh-database-runner.ts baseline /private/review.json /private/input.json /private/baseline.json
TSX_DISABLE_CACHE=1 TSX_TSCONFIG_PATH=prisma/tsconfig.fresh-database.json node --import tsx prisma/fresh-database-runner.ts prep /private/config.json /private/approval.json APPROVAL_SHA256_FROM_COORDINATOR /private/preparation.json
```

`validate`, `baseline`, and `prep` are offline. The same runner's `run /private/config.json /private/approval.json APPROVAL_SHA256_FROM_COORDINATOR` is the **only connecting command**, and requires separately registered runtime/Board/cloud admission. It was NOT RUN. Module imports do not execute it. Legacy `prisma/bootstrap.ts` is never imported.

Files containing configuration, CA or review data must be owned by the invoking user, regular, single-link, at most 16 MiB, and mode 0600 or stricter. Symlink input files fail. No dotenv, default credentials, or inherited `PG*`, `DEBUG`, or `NODE_DEBUG` settings are accepted. A CA is explicit bytes, not an environment trust override. The example JSON uses private-test-only synthetic values and cannot authorize execution.

The config must contain every key in `fresh-database-runner.ts`'s strict schema. `sourceRoot` must be the directory containing the executing source. `artifactSha256` binds the exact artifact file bytes. The config approval field is only a consistency label, not approval authority; it includes the `reviewId`, exact target, and SHA-256 of `stable(endpoint)` from the fingerprint module. Both migration/runtime URLs remain mandatory under the existing contract; only the validated runtime URL constructs a client. Real endpoint, CA, administrator identities and unique secrets are execution inputs, never guessed here.

`baseline` input is `{ "sourceRoot": "...", "env": { ...all explicit Restaurant input keys... } }`. Its review is the `OfflineReview` data structure exported by `fresh-database-baseline.ts`: version/provenance/purpose/review ID, source hash map, public intent hash, endpoint, complete fingerprint plan, independently reviewed INITIAL and COMPLETED expected rows, catalog facts and runtime role facts. `sourceContextPaths(root)` enumerates the exact files that must be independently pinned; hash raw bytes, not parsed/reformatted objects. The artifact generator regenerates and verifies all bindings. It never receives a DB handle or turns observations into approved data. The tests contain executable, complete 451-model **synthetic-only** examples; they are not real catalog/row approval.

## Independent approval and unresolved historical inputs

`run`, `validate` and `prep` now require a **separate** private receipt file and its SHA-256 as separate caller arguments. The pin must come from the coordinator's authenticated independent-review channel, never from the mutable private config or baseline artifact. A missing pin, same file, changed bytes, wrong source/target/endpoint/intent/artifact/purpose, or missing reviewer/session/time rejects before driver allocation. `runPrivate(path, binding)` and `loadPrivateConfig(path, binding)` take `{file, sha256}`; calls without binding fail closed. This is an intentional private-command contract adjustment. The existing config schema remains intact for consistency checks.

The receipt is strict JSON: `version: "restaurant-independent-approval-v1"`, `reviewId`, `reviewer`, ISO UTC `reviewedAt`, `session`, `target`, `purpose`, raw-file `artifactSha256`, and `sourceSha256`, `intentSha256`, `endpointSha256`. Source/endpoint hashes use `digest` of the complete review source map/endpoint; purpose is exactly INITIAL_TRANSITION or COMPLETED_REPLAY. The receipt must be independently reviewed after baseline generation. Hash binding provides integrity relative to an externally trusted pin; it does **not** authenticate who wrote the receipt or create approval from a label. Do not derive the trusted pin from a receipt the executor has just created. Synthetic tests establish byte/mismatch refusal, not independent human approval.

**Unresolved execution input gate:** migrations create historical `org_devfathom` and department timestamps using CURRENT_TIMESTAMP. Their real exact values cannot be predicted offline. This patch does not implement or authorize a target capture, and no genuine INITIAL artifact is provided. Coordinator must separately approve a read-only historical capture procedure/artifact with who/when/session, exact target and source binding, and review all historical values plus catalog facts before issuing an external approval pin. A live observation must never be silently promoted to approval. Until that procedure and genuine inputs exist, INITIAL execution remains held. Historical fields are never normalized; timestamp drift remains detectable. COMPLETED requires its own independent exact-state evidence and approval.

## Two explicit artifact purposes

`INITIAL_TRANSITION` approves a fresh transition. First observation must match INITIAL. After the writer, generated IDs, their declared FK references, and exact declared new timestamp fields may normalize. Created selectors must be absent in INITIAL, unique in COMPLETED and restricted to canonical writer tables/effects. Selectors can use `@ref:<earlier-created-token>` only through a declared FK. Historical `org_devfathom`, its departments, existing catalog rows and all unrelated rows retain exact values. Two intended administrator password fields normalize only after bcrypt verification against supplied secrets and algorithm/cost 2a/2b, 12. They use explicit `@initial-password:admin` / `@initial-password:platform` offline markers; no arbitrary hashes/tokens are exempted.

`COMPLETED_REPLAY` is a **separate independently reviewed artifact**, with `plan.created=[]`. It fingerprints exact stored IDs, timestamps, password hashes, roles, status, permissions and every other field. First and subsequent observations must match its COMPLETED state. This permits an explicit review of legitimate account changes without repairing them. The initial transition artifact is deliberately not reusable as replay approval: unknown salted hash bytes cannot be independently predicted, and the initializer must not learn approval from its connected target. No automatic artifact capture/promotion is implemented.

The versioned row encoding includes every table/column/type and FK relationship, row count, duplicate-key detection and reference checks. Column reads use PostgreSQL text under UTC/ISO/hex/extra_float_digits=3. `restaurant-state-v2` preserves exact text/scale for plain numeric/decimal (1.50 differs from 1.5); declared numeric precision/scale and JSON numeric canonicalization retain value semantics. Old v1 plans reject and require regeneration/review; JSON object keys and rows sort deterministically. NULL remains distinct from strings, empty values, false and zero. Timestamp fractions and byte data remain intact. Unknown/omitted tables or columns reject.

## Visibility and catalog proof

The observer binds Prisma's transaction object to its actual checked-out pg client, verifies authorized TLS, peer hostname, CA bytes, configured endpoint, socket servername/remote port and backend PID, then measures role/current_user/session_user/database, ledger, catalog and rows on that same transaction. The existing guard checks the 125-row migration ledger. The observer rejects RLS on the ledger itself.

Catalog facts cover application relations, columns/types/defaults/ACLs, keys/FKs/validity, policy expressions/roles/permissiveness, functions and execution ACLs, triggers, extensions, schemas, database/default ACLs, sequences, enums, applicable role/database settings from pg_db_role_setting, and non-view pg_rewrite definitions. The last two sections are mandatory even when empty; this version conservatively refuses all applicable defaults or non-view rules, including platform-admin defaults. Catalog access failure also refuses; it never widens grants. Index metadata is retained but index columns are not treated as application SELECT grants. Exact catalog bytes in the review must match exact live catalog facts. Application coverage must independently match all 451 pinned Prisma models. Runtime ownership, memberships, SUPERUSER/BYPASS/INHERIT/role-management privileges, CREATE/TEMP, blanket table DML, UPDATE/DELETE/TRUNCATE and non-writer column INSERT privileges reject.

Supported SELECT policies compare exact pg_get_expr text, including casts, whitespace, quoted identifiers, literal bytes and grouping. No lowercasing or whitespace removal occurs. Nonmatching formatting fails closed and requires review; actual server deparse compatibility remains unproven offline. Supported forms are: direct platform-admin visibility (including nullable organization rows), strict organization scope with validated nonnullable anchors, optional branch with cleared branch context, and strict organization/branch with a validated nonnullable composite FK to globally visible restaurant branches. All org/branch pairs are enumerated, including branches whose organizations are absent. Three GUCs are saved/restored even on error and before the writer. Referenced functions and all policies remain source/catalog-bound; unknown functions, parent-EXISTS forms, restrictive policies, hidden/missing objects and unsupported forms reject before fingerprinting.

**Known source gate:** `pharmacy_migration_sources` has a strict organization policy without a reviewed validated organization anchor in its defining migration. If the actual same-TX catalog has that gap, complete visibility fails. Descendants cannot establish coverage through an unanchored source. No live catalog was inspected, no RLS/role/schema/grant widening was introduced, and zero rows never constitute visibility proof. Other unsupported policy forms may also block admission.

## Driver and outcome contract

Locked code is pg **8.22.0** and adapter-pg **7.9.1** (the package range starts at ^8.20.0). Runtime checks pin versions and six driver files. Actual SQL COMMIT goes through adapter `performIO`; `PgTransaction.commit()` merely releases. The adapter wraps every physical `Query.submit`, including queued COMMIT, and rechecks deadline, cancellation and exact TLS connection. It never relies on `query_timeout` for server cancellation. Server statement/lock/idle-transaction timeouts complement the physical dispatch latch.

Cancellation destroys all owned connecting/checked-out sockets and waits for driver operations, transaction settlement and actual client `end` events. Checked-out clients are released before pool shutdown. Close and cancellation are idempotent; partial allocation/connect and cleanup failure are covered. No detached Promise.race returns while owned local work remains. A driver or OS that never settles can therefore keep the process waiting; it cannot be safely relabeled as successful rollback.

`COMMITTED` requires an observed COMMIT acknowledgement within the boundary. A dispatched COMMIT without acknowledgement, late acknowledgement, or cleanup failure is `UNKNOWN`. Socket closure is **not** server rollback proof. `ROLLED_BACK` requires actual ROLLBACK acknowledgement before a dispatched commit. The receipt reports only closed outcome/code/manual-review fields, never SQL, URLs, credentials or exception values. Late cancellation after a timely observed commit preserves the known commit fact but can still require review. SIGINT/SIGTERM latch cancellation; no retry occurs.

Fake-driver tests establish local dispatch and settlement invariants only, including COMMIT receiving a ROLLBACK tag (UNKNOWN), late ACK, queued mutation refusal after socket cancellation, and waiting for an owned end event. pg.Pool/query queues, result messages and TLS properties remain mocked. Registered live TLS/CA/role/ACL/visibility, connection cancellation, server rollback, lost-response, concurrency and replay evidence remains mandatory before any execution acceptance.

## Preparation and composition

`fresh-database-migrate.config.ts` is an explicit migration-only Prisma config (no dotenv or seed); use it only in the owner's separately approved migration workflow against all 125 unchanged SQL files. No migration or psql process is started here. `renderPreparation` emits offline btree_gist/pg_trgm extension preparation and individual observer SELECT plus exact INSERT-column grants for the ten writer tables. Query-shape tests run both syncPlatformCatalog(tx, scope) and bootstrapProduction(tx, input) through the real generated Prisma client with synthetic pg result rows; emitted physical SQL covers upsert, createMany, and nested permissions. This source capture emits no UPDATE and keeps every INSERT within the frozen column grants; the union per table matches all ten grant lists. Non-core package links omit optional limits, and every fresh link is captured. It does not prove server privilege execution, the real pg queue, TLS, or catalog output. No ALL/default grants, role switching, ownership, BYPASS, TEMP, DELETE/TRUNCATE or blanket DML are emitted. Existing wider grants need independent review/revocation; the renderer does not change them. A future compiler needing additional privileges must fail closed and undergo exact review.

Composer dependencies: selected frozen 141-file source context, unchanged 459-file/451-model generated client, fixed package/lock, pg 8.22.0, adapter-pg/client 7.9.1, bcryptjs, zod, tsx, TypeScript and scoped lint tooling. `SOURCE_CONTEXT_DEPENDENCIES.json` and admission receipt enumerate exact files/hashes. No dependencies were installed, no full clone/image/build occurred, and the 17 demo imports remain untouched. Composer owns source/Docker manifest refresh and all later release gates.
